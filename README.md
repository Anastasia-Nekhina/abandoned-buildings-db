# Проект: Ликвидация заброшенных объектов в Московской области

## О проекте

Комплексная система анализа, пространственного моделирования и прогнозирования для заброшенных объектов недвижимости на территории Московской области. Проект включает полный ETL-пайплайн: от подготовки данных из Excel-файлов до построения ML-моделей.

---

## Архитектура проекта
Исходные данные (Excel, GPKG)
↓

data_preparing.py → Очистка, нормализация, создание CSV/GDF
↓

data_load.py → Загрузка в PostgreSQL/PostGIS
↓
3–5. Скрипты QGIS → Пространственный анализ (буферы, расстояния и тд)
↓

new_data_spatial_qgis.py → Расчет 27 пространственных признаков
↓
7–8. Формирование стратифицированной выборки (120 объектов)
↓
9–11. Анализ пропусков, расчет ЖЦ здания, проверка гипотезы о пожарах
↓

data_prediction_final.py → Обучение моделей (GradientBoosting + RidgeCV)
↓

data_prediction_final_executing.py → Прогноз на полный датасет

---

## Структура репозитория

### Python-скрипты (ядро обработки)

| Файл | Назначение |
|------|------------|
| `data_preparing.py` | Чтение Excel-файлов, очистка координат и кадастровых номеров, приведение типов, создание GeoDataFrame |
| `data_load.py` | Загрузка данных в PostgreSQL (создание схемы, справочников, внешних ключей) |
| `data_load_boundaries.py` | Загрузка границ муниципалитетов и населенных пунктов, удаление объектов вне МО |
| `data_prediction_final.py` | Обучение моделей: корреляционный анализ, отбор признаков, GradientBoostingRegressor (complexity) и RidgeCV (priority) |
| `data_prediction_final_executing.py` | Применение обученных моделей к полному датасету, запись результатов в БД |

### QGIS-скрипты (пространственный анализ)

| Файл | Назначение |
|------|------------|
| `new_data_municipalities_qgis.py` | Очистка названий муниципалитетов для сопоставления |
| `new_data_population_qgis.py` | Извлечение плотности населения из растра |
| `new_data_spatial_qgis.py` | **Ключевой скрипт:** расчет 27 пространственных признаков (расстояния до дорог, POI, пожаров, воды, коммерческих/промышленных зон; буферные подсчеты; флаги попадания в зоны) |
| `new_data_end_date_qgis.py` | Расчет даты окончания жизненного цикла объекта (для анализа пожаров) |
| `representative_points_qgis.py` | Формирование стратифицированной выборки (120 объектов) с сохранением пропорций категорий |
| `table_for_formulas_qgis.py` | Джойн дополнительных таблиц (`mkd_info`, `okn_info`, `uc_info`, `checklists`) к выборке |
| `check_attributes_for_nulls_qgis.py` | Анализ пропусков и уникальных значений в выборке |

### Файлы анализа и проверки

| Файл | Назначение |
|------|------------|
| `checking_connection_fires_buildings.py` | CDF-тест для проверки связи между заброшенными зданиями и близостью пожаров |
| `db_fire_dist.sql` | SQL-запрос для расчета расстояний от пожаров до ближайших зданий |
| `db_municipalities_stats.sql` | Создание материализованного представления с агрегированными пространственными метриками по муниципалитетам |
| `db_query_demolition_time.sql` | Расчет медианного времени от постановки на учет до сноса |

### Схема базы данных

| Файл | Назначение |
|------|------------|
| `db_schema_DDL.sql` | Полная схема БД: 9 таблиц (объекты, справочники, расширения МКД/ОКН/самовольных, исполнители, статусы, чек-листы, судопроизводства) |
| `db_delete.sql` | Сброс и пересоздание схемы public с расширением PostGIS |
